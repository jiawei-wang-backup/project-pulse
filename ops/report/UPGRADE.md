# 上报包更新与部署

## 3.1.1 宽松Agent识别

更新真正服务端并重启，使运行计数、卡片和会话列表共用宽松规则：running的近期窗口为2小时，unknown须近30分钟用量证据，明确终止状态不计入。客户端更新后可依据新消息、输出、工具调用和新增用量补足缺失开始事件。项目状态仍无时间超时，Agent判断与项目生命周期独立。若009迁移已应用，本修订无需额外迁移。

## 3.1.0 项目状态与统计修订

真正服务端先执行db/009_project_lifecycle.sql（已有部署先确认008迁移也已应用）并按原方式重启。迁移保留历史记录，扩展completed／paused状态及判断依据，不依赖时间超时。服务端增加client_project_status能力。客户端覆盖更新脚本和提示词后，更新已有30分钟任务：按会话证据判断状态，写statuses.json并核对status_receipt；下班、会议、无新日志不能改变项目生命周期。

UI“在研项目”包含on_track与blocked，独立于Agent执行；产出文档按项目可折叠；成员参与项目使用长期关系与近期会话的并集；Token查询统一按UTC+8自然日起点和同一快照上限，缓存输入不重复加总。删除右上角时间标签不改变统计时区。

以下记录为旧修订历史；其中“无需新增迁移”不适用于此次3.1.0升级。

客户端全量识别修订：项目、会话、仓库／PR、Token、摘要和里程碑全部由客户端Codex主动查证整理，只有自行查找后仍缺信息才询问用户。新增pulls.json和POST /api/v1/report-pulls，独立PR回执、失败续传和幂等，不改动Token游标。真正服务端需拉取更新并重启以提供client_pr_ingest能力；旧服务端的PR抓取仅为管理员可选补充，不能代替客户端本轮工作。客户端覆盖更新后必须更新已有30分钟任务正文，不能只更新脚本而保留旧提示词。

同名目录识别由客户端Codex负责：在限定候选范围内结合会话摘要、README、Git remote和近期提交判断。唯一且证据一致的迁移候选直接写入私有路径映射并记录依据，不再一律要求用户填写；仅有歧义或冲突才追问。本项更新提示词即可生效，无服务端协议变化；已有定时任务须更新提示词并读取最新版README。

项目cwd迁移修订：新增私有 `.pulse-project-paths.json` 映射及核实后缓存，保留该文件；ZIP仅提供不含本机路径的示例。服务端新增 project_mapping_backfill 能力，支持在不重传Token、不推进游标时修正既有会话与其里程碑的项目归属。真正服务端必须更新并重启后才可补报旧记录，无需数据库迁移。仅客户端更新时，新日志可使用新映射，旧记录补报会明确提示服务端缺少能力。

本修订新增Linux入口 `pulse-report-linux.sh`，复用同一Perl采集核心；Windows脚本独立，服务端协议仍为3。Linux采用machine-id+UID，缺少machine-id时使用当前用户私有持久标识。包内不包含任何已生成的设备标识或状态。Linux新增CI，验证长元数据、Token差分、续传、迁移及回执核验；定时能力由实际执行工具提供。

本包版本 3.0.0，需要服务端协议 3。管理员先在真正服务端拉取仓库更新并用原部署方式重启 Node 服务。无需新数据库迁移。不要在客户端启动服务端。只有服务端 `/api/v1/report-directory` 返回 `protocol_version: 3` 后才能使用本包。

此修订增加Codex账号目录的有界发现与已确认根目录缓存。新旧目录里的相同原生会话ID共用游标；更换Codex登录账号不改变团队身份。日志根目录为0或发现未完成时，必须提示用户确认新位置，不能将其当作零用量。只更新客户端包即可启用这项能力，服务端协议仍为3。

更新客户端时，先查看现有任务和工作目录，暂停同用途任务，确认没有上报正在执行。将新 ZIP 解压到原来的永久目录，覆盖包内的程序和说明文件，保留 `.pulse-state-*.json` 和 `.pulse-pending/`。状态文件不包含日志原文或令牌，只保存固定采集起点、轮转位置、已确认账号和待续传目录；待续传目录包含结构化请求，应保留为当前用户私有。

再次发送 PROMPT.txt，脚本会检查服务端能力并优先重试待发请求。试报成功后更新并启用原任务，核对工作目录、提示词版本、实际计划和启用状态。不要重复创建，也不要把工作目录换成新建的临时文件夹。复制出的旧包不会自动更新；每次升级都必须核对 VERSION 和 SHA256SUMS。

3.0.0 不会追溯修改已经提交的历史 Token。旧版漏计或错误归属需依据原始日志另做受控核对，不能通过重置游标或清空数据库重复导入来修复。

测试分两层：自动化测试验证固定脚本与服务端事务；真实定时验收必须等到至少一次自动触发，记录任务运行时间、批次回执或无新增诊断。仅查到任务存在时只能报告“已设置，首次自动运行待验证”。离线、休眠或工具无法调度时如实报告；恢复后沿已确认游标继续。GitHub PR 同步另由服务端调度，客户端的30分钟任务不替代它。
