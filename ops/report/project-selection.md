# 先选项目，再上报

## 第一次配置或用户重新选择

1. 先做只读盘点。读取当前用户授权范围内Codex主会话的元数据（原生会话ID、项目工作目录、Git仓库信息），结合本包已有路径映射和授权目录内Git remote识别项目。允许GET服务端目录来核对已登记仓库。此时不要执行Prepare／Submit、POST上报、团队修改或创建定时任务：Prepare可能自动续传旧批次，不能用它做无副作用的项目预览。
2. 仅列出本机存在相关会话或明确工作目录证据的项目；服务端其他成员的仓库不能当成本机项目。Git远端相同的迁移路径归为一个项目；只有目录同名而无充分证据时分开显示并注明待确认。工作区无远端则保留本地项目，不强行认作GitHub仓库。排除当前上报会话和子Agent重复记录。先读文件头等基本元数据，不从头重做所有会话总结，不读取未授权目录或登录凭证。
3. 展示编号列表或表格：项目名称、确认的owner/repo或本地工作区、已识别主会话数量、归属是否待确认。计数不完整或有界扫描未完成时明确标注，不能把部分结果说成全部项目。请用户回复编号，支持多选、明确选择“全部已列出的项目”或“暂不上报”。不要默认全选，不把沉默当成选择。必要时把身份或映射疑问与项目选择一起集中询问。
4. 等用户明确选择后，才将选择保存到本包私有 `.pulse-project-selection.json`。记录已选项目的规范仓库／工作区身份、已确认目录别名、源会话UUID及确认时间；只留在本机，不上传、不提交Git、不打入分发ZIP。用户未选择时停在此步骤，不提交已确认数据，也不创建或更新定时任务。

建议私有文件结构（值必须来自实际识别和用户选择）：

```json
{
  "schema_version": 1,
  "confirmed_at": "用户确认时的UTC时间",
  "projects": [
    {
      "repository": "owner/repo或null",
      "workspace_name": "项目工作区名称",
      "workspace_aliases": ["本机已确认目录"],
      "source_ids": ["已确认的主会话UUID"]
    }
  ]
}
```

## 选择后继续完整流程

读取私有选择，明确本轮授权的源会话UUID，之后才运行Prepare。macOS／Linux给每个选中源重复传 `--only-source <UUID>`，Windows用 `-OnlySource @('<UUID1>','<UUID2>')`，并对Submit传相同范围。Windows数组需要在PowerShell会话内调用脚本，不能把含数组的命令当作原生命令行的一个字符串。不要传空数组后无范围运行；空选择表示不执行上报。

只为所选项目读取必要会话增量、核验仓库及PR、生成摘要／目标／里程碑和项目状态，并核对Token、PR、状态回执；未选项目不进入本轮日志、PR或状态提交。团队数据修正仍需明确需求与证据，不能借此绕过所选上报范围批量改其他项目。既有待续传批次包含未选源时脚本会停止；保留原文件、游标和回执，向用户说明冲突并重新确认处理方式，不能擅自上传、删除或重置。

## 每30分钟任务

试报成功后创建或更新并启用原来的30分钟任务。任务正文必须写明：读取本包私有选择，仅对所选项目识别和增量同步；每轮将实际确认的source_ids作为OnlySource范围。选择文件缺失、损坏、为空或归属有歧义时停止并明确报告，不退回全量上报。

自动运行不每轮询问同一份选择。已选仓库的新主会话可在Git remote或已确认映射能唯一证明归属时加入该项目并更新source_ids；无法证实时暂不上传并询问。新发现的其他项目不自动加入，留待用户明确选择。需要改范围时再次列出候选，用户确认后更新私有文件与已有任务，不创建重复任务。每次结果报告所选项目、未选跳过范围、是否还有积压，以及实际任务启用状态。
